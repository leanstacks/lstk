# PLAN-0027 — Update the guides for the `plan-author` skill

**Source:** GitHub issue 27.

## Context

`plan-author` shipped in `lstk` 0.5.0. `lifecycle.md` (Plan section) and `faq.md` ("plan-author or plan mode?") cover it.
The two task guides do not. `existing-projects.md` and `new-projects.md` still tell the reader to use plain plan mode at
every planning step. Issue 27 asks us to decide where each guide should point at `/lstk:plan-author`, and to update them.
This is docs only: no plugin change, so no version bump. Per AGENTS.md, a plan for this work also needs a row in
`docs/plans/README.md` (this plan will be saved as `docs/plans/PLAN-0027.md`).

## Decision (the issue's question)

Rule, taken from faq.md and lifecycle.md: plan mode is the default for one-session work. `plan-author` is for work whose
plan must outlive the session (multi-session, handoff between sessions, or a plan the team reviews as a file).
Apply it as an optional branch, not a replacement, so the loop stays plain-Claude-Code-first.

| Location                                                                                                    | Change                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `existing-projects.md`, Shared loop step 2                                                                  | Keep plan mode as default. Add: if the change spans several sessions, run `/lstk:plan-author` (leave plan mode first) and implement phase by phase from the saved file. Tag `[type it]` for that branch. Add a prompt block and update "What lstk adds" and "What is plain Claude Code" (line ~101) so planning is no longer listed as purely plain. |
| `existing-projects.md`, Add a feature (step 5 + prompt, line ~155) and "plain Claude Code here" (line ~175) | Larger features (those that already ran `solution-outline`) are the natural fit: offer `plan-author` with the design doc as input. Small features stay in plan mode. Fix the "Planning in plan mode" sentence.                                                                                                                                       |
| `existing-projects.md`, Enhance / Fix a bug                                                                 | Enhance: mention only if large (one line). Fix a bug: no change (single session).                                                                                                                                                                                                                                                                    |
| `new-projects.md`, step 3 (skeleton, line ~129) and prompt (line ~165)                                      | Keep plan mode for the skeleton (one session). Add a short note: for a greenfield system with several milestones after the skeleton, run `/lstk:plan-author` in milestone mode against the stack brief and outline. Do not renumber steps. Add as an optional step or a sentence under step 3.                                                       |
| `new-projects.md`, prototype Step 5 "gap list short enough to plan from" (line ~254)                        | Optional one-line pointer: for a long gap list, `plan-author` turns it into a phase plan.                                                                                                                                                                                                                                                            |
| Both guides, header "Last verified" note                                                                    | Update to reflect `lstk` 0.5.0. Do **not** claim a verified run that we did not do: either state the plan-author additions are unverified, or run the skill on the fixture first (see Verification).                                                                                                                                                 |
| `lifecycle.md`, `faq.md`                                                                                    | Already correct. Add links to the new guide sections if useful. `walkthrough-bug-fix.md`, `review-and-hardening.md`: no change.                                                                                                                                                                                                                      |

Keep the existing guide conventions: step tags (`[type it]`), "Produces" (`docs/plans/PLAN-<id>.md` plus an index row),
"Skip it when", Example Orders names. Link `../examples/plan-author.md` as the example.
